## Canonical gameplay state
- browser-first TypeScript, 6x5 merge board;
- sequential T1-T8 chain: Toilet Buddy -> Camera Dude -> Sigma Rock -> Rizz Head -> Shark Sneakers -> Crocodile Bomber -> Coffee Ballerina -> Tung Wood;
- two identical characters become exactly one next-tier character;

## Approved upgrade/offline art integration
The user supplied production artwork for Base Drop Tier, Lucky +1, Global Income, Offline Capacity and Offline Reward.

Integration follows the existing code-first UI architecture rather than flattening screens into images:
- runtime sprite: `public/assets/ui/upgrade-ui-atlas.webp`;

## UI architecture cleanup completed
A full CSS ownership audit found that the upgrade-art layer had inherited responsive repair rules from earlier polish passes. That was architecturally wrong: presentation art should not decide whether Mission, Collection or Brain Lab panels are visible or where they are ordered.

Responsibility is now explicit:
- `public/code-ui.css` remains the structural code-first component layer;
- feature CSS layers own feature-specific appearance/states;
- `public/upgrade-art.css` is presentation-only and contains no Mission/right-rail composition rules;
- `public/mobile-runtime.css` is the final responsive composition authority;
- at <=1180px the board is first, Mission follows, then a reachable two-column right rail;
- at phone widths the rail becomes one column with Brain Lab before Collection;
- `public/accessibility.css` remains the final interaction override layer.

`tests/ui-contract.test.mjs` now guards stylesheet ordering, prevents upgrade art from taking responsive ownership, requires production panels to remain reachable and checks that Brain Lab state/actions are still generated by code.

## Keyboard/input hardening completed at source level
A real accidental-spend risk was found in `src/main.ts`: pressing global Space while body-focused bought a paid Brain Box. That shortcut has been removed.

Board keyboard behavior now mirrors the existing gameplay path:
- Enter or Space on a focused board cell calls the same select/move/merge action used by pointer interaction;
- ArrowLeft/Right/Up/Down move focus using the canonical board column count and never spend currency;
- Escape clears board selection;
- M remains a safe body-level mute toggle;
- `GameView` rerenders replace DOM nodes, so `activateCell()` explicitly restores keyboard focus to the target cell after a synchronous rerender;
- focus-visible and coarse-pointer CSS remain intact.

This is source/CI-level hardening. Real browser keyboard/touch/mouse smoke is still required before the final runtime QA gate is closed.

## Validation status
The UI ownership/keyboard pass introduced contract tests. One CI run first caught a TypeScript focus-target type issue; it was corrected by returning `HTMLElement | null` from `cellElement()`. A subsequent run exposed two overly broad assertions in the new test itself (comment text matching `order:` and over-escaped source matching); the assertions were narrowed to structural selectors/source syntax.

The gameplay/economy/platform tests, TypeScript build and Yandex package are unchanged in behavior by this pass. Final green CI for the latest documentation HEAD must be checked before claiming the pass fully validated.
